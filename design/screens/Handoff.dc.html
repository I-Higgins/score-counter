3b. Layouts and breakpoints

  • Phone portrait (under 600 wide): one column of cards, 84 high (64 compact at 6 or more players). End round pinned at the bottom. Artboard 1.
  • Tablet portrait (600 wide and up, taller than wide): two-column grid of cards, 136 high, with 76×72 plates and 48 pt score, filling in reading order. A "This game so far" table sits below, and "Full table" plus "End round" pinned at the bottom. Artboards 15 and 16; round entry splits into a player list on the left and a 340-wide keypad on the right.
  • Tablet landscape (wider than tall, 900 high or less): two-column card grid on the left, and a 340-wide sidebar on the right holding the round card, a players × rounds mini table and End round. Artboard 17.
  • Phone landscape (450 high or less): a fallback, not a lock. Two columns of 64-high cards, with a 176-wide side rail for actions, round and End round. It respects the notch safe areas. Artboard 18.
  • Use @media (orientation) plus width and height queries, not user-agent sniffing. The manifest sets "orientation": "portrait" as a hint, but iOS ignores it, so every layout above must work.

4. Behaviour rules

  • Sorting: by total plus this-round amount. Re-sort waits after the last tap: Quick 500ms, Normal 900ms (default), Relaxed 1500ms. Each tap restarts the timer, and no reorder happens while a finger is down.
  • Reorder animation: FLIP translate at --motion-reorder, then the moved row gets a ring for 600ms. With reduced motion: no movement, rows swap in place and the ring fades in at --motion-fade.
  • Rank: shared rank (1, 1, 3). "Leading" shows on every player tied for best, and is hidden when everyone is equal.
  • Marker: dealer or first player moves one seat on each saved round, following the manual seat order, not the sort order.
  • Game end: target reached (checked after saving a round), or the last round saved. Show the game-over screen; ties are shared wins.
  • Save: write to IndexedDB on every change, with no save button. On launch, restore the exact screen and state, including a half-entered round.
  • Undo: a stack of the last 50 changes within the current game, kept across relaunch.
  • Update banner: held back while round entry is open.
  • Keep screen on: Wake Lock while a game screen is visible; re-request it on visibilitychange. Fail silently.

Group     { id, name, players: [{ id, name, color, seat }], createdAt }
GameType  { id, name, builtIn, winner: "high"|"low",
            end: { kind: "target"|"lastRound"|"none", target? },
            rounds: { show, start, end, label: "cardsWild"|"number" },
            marker: "dealer"|"first"|"none", quick: [int] }
Match     { id, groupId|null, game: GameType (snapshot), playerIds,
            rounds: [{ n, scores: { [playerId]: int } }],
            pending: { [playerId]: int }, markerSeat, startedAt, endedAt?, winnerIds? }
Settings  (localStorage) { theme, textSize, sortDelay, keepAwake }

Share link: https://<user>.github.io/score-counter/#game=<base64url(JSON {v:1, game})>
  · the fragment never reaches the server · only the GameType, never ids, names or scores
  · on import: validate schema, cap name at 40 chars, ints within ±100000, ≤8 quick buttons
  · always ask before saving; a name clash adds alongside, never overwrites
Backup file: score-counter-backup-YYYY-MM-DD.json, everything above plus a schema version.

Stats are derived from finished Matches. Never store them separately. A Quick game has groupId null and is excluded from stats.

6. Follow exactly vs freedom

Follow exactly

  • Tokens, player palette, and dark text on every card
  • Touch targets of 44 or more; plate and key sizes
  • Sort timing, freeze-while-touching, shared rank
  • No reload mid-game; instant save; exact resume
  • Share link carries rules only, and always asks before importing

Freedom

  • Icon stroke details and the exact menu layout
  • Copy tweaks, as long as they stay short and plain
  • Exact sidebar width in landscape (300–360 is fine)
  • Empty-state illustrations beyond first launch
